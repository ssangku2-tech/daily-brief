# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

"My Agent" — a single-page PWA (no build step, no framework, no package.json) that shows a Korean user one screen of daily briefing: overnight US market moves, news for their watchlist stocks, Anthropic news, and their own schedule, mail, and (later) assets. It is served as static files (GitHub Pages). Everything the app needs lives in three files: `index.html` (markup + CSS + JS in one file), `sw.js` (service worker), `manifest.json` (PWA manifest).

The app is at v0.3. The US market card (관심 종목 + 주요 뉴스 + 앤트로픽) exists; the 자산 card is a link-out placeholder.

**Everything the user reads refreshes at access time (as of 2026-08-07); the daily files are the fallback.** Prices, news, and unread mail are all fetched client-side on every load/refresh; `briefings/` and `agenda/` are what renders when those fetches fail or the user is offline. The one thing that *cannot* move client-side is anything Claude writes — the briefing's `summary`, each headline's `ko` line, and the mail-importance summaries — because a client-side LLM call would bill tokens on every app open. Those stay in the daily files. **Translation, however, is not an LLM job here** — see the 제목 번역 note below: headlines are Koreanized at access time through Google Translate's free public endpoint, so a story that arrived minutes ago still reads in Korean.
- **Prices**: `index.html` calls the Cloudflare Worker directly and overwrites the briefing file's price/changePct. The Worker sends `Access-Control-Allow-Origin: *`, so the browser can call it with no proxy.
- **News** (`loadNews`): also through that Worker, which turned out to have a **generic `?url=<encoded>` proxy** and a **`?news=<ticker>` endpoint** (both used by the portfolio app) alongside `?symbol=`. Both send `Access-Control-Allow-Origin: *`. This reversed the old "news can't be client-side" conclusion — that was true of *Google News RSS specifically* (no CORS headers, `Cross-Origin-Resource-Policy: same-site`), and it stays true even through the proxy: **Google blocks Cloudflare datacenter IPs and answers the Worker with a 503 "Sorry..." page**, verified. So the client uses different sources than `generate.js` does. Before adding any feed, curl it through `?url=` and confirm real XML comes back — Bing News and Yahoo News search both dropped RSS and return HTML now.
  - 주요 뉴스: CNBC 마켓 + CNBC 주요 뉴스 RSS, deduped by link, sorted by `ts` (a real epoch, not the display date string — one feed's items would otherwise shuffle within a day), top 5. Two feeds because the markets feed alone posts too rarely to fill 5 slots without reaching a week back.
  - 종목 뉴스: `?news=<ticker>` per `WATCH` entry (Yahoo for US tickers, Naver for 6-digit KR codes; sometimes carries a `titleKo` the Worker translated). That feed is a *sector* feed, so each `WATCH` entry has a `re` that pulls company-matching items to the front — it does **not** filter the rest out, since empty per-stock blocks were the original complaint.
  - 앤트로픽: TechCrunch's `anthropic` tag feed, filtered by `/anthropic|claude/i` (the tag feed carries adjacent stories too).
- **제목 번역** (`translateNews`, 2026-08-07): the live feeds are English, and `koMapOf` can only reuse the morning `ko` for stories that already existed at 06:30 — so anything new stayed English. The fix is **Google Translate's public endpoint**, not an LLM: no key, no billing, `Access-Control-Allow-Origin: *` so the browser calls it directly. Use `translate_a/t?client=dict-chrome-ex`, which takes **repeated `q=` params and returns the translations as an array in the same order**; the more commonly cited `translate_a/single?client=gtx` translates only the *first* `q` and would need one request per headline. 8 titles come back in ~0.7s. Details worth keeping: results are cached in `localStorage` (`mytrans_v1`, 400 entries, oldest trimmed) so a re-open usually issues **zero** requests (verified: 2 requests on first load, 0 on reload); requests are chunked to keep the GET URL under ~1600 chars; `needsKo()` skips titles that are already Korean (Naver stock news, the Worker's own `titleKo`); a failure falls back to the `WORKER_URL` `?url=` proxy and then, silently, to the English original. `refreshAll` renders *before* awaiting the translation, so a slow translate never delays the news itself.
- **Schedule and mail** (`loadGoogleLive`): browser-side Calendar/Gmail APIs on one shared token, gated on `GOOGLE_WEB_CLIENT_ID` — see the 일정·메일 note under Known gaps. Off until that constant is filled in.

None of these paths calls an LLM, so opening or refreshing the app any number of times still costs zero tokens. Per-access traffic is now ~20 Worker requests (10 quotes + 9 news + …), 2 static JSON files, 0–2 Google Translate requests (0 once the day's headlines are cached), up to 10 Gmail requests if live mail is on, and (at most once per 30 min) 2 weather requests. **Growing that count is only acceptable because every one of those calls is free.** The single remaining per-day LLM call in the whole project is `generate-agenda.js`'s mail-importance pass, plus `generate.js`'s one `enrichKorean()` call, both in CI and both unaffected by how often the app is opened.

**Generation pipeline (implemented):** `.github/workflows/daily.yml` runs on a cron (`30 21 * * *` UTC = KST 06:30, plus manual `workflow_dispatch`, plus three retry firings) and calls `scripts/generate.js`, which writes `briefings/YYYY-MM-DD.json`, then regenerates `briefings/index.json` from the files actually present in the directory. It skips generation if the day's file already exists, and commits/pushes only when `briefings/` actually changed. It also skips when `dateKey` (the KST calendar day, not "now") falls on Saturday or Sunday — the US market is closed those days, so a Sat/Sun run would just regenerate the same already-published Friday session under a new filename. This must be checked against `dateKey`, not against the current moment converted to US Eastern time: a KST Monday-morning run is still Sunday night in US Eastern, so checking "now" would wrongly skip Monday's run too (which is the first run that's actually due to look for a new session). The weekday check (`weekdayOf()` in `generate.js`) computes this from `dateKey` using UTC-only `Date` methods (`` `${dateStr}T00:00:00Z` `` + `.getUTCDay()`) rather than `.getDay()` — `.getDay()` follows the *process's* local timezone, and on a GitHub Actions runner (UTC) the older `` `${dateKey}T00:00:00+09:00` `` + `.getDay()` form actually computed the wrong weekday (it only ever looked correct when tested on a KST-timezone dev machine). This was a live, unnoticed bug fixed 2026-08-05 — the code hadn't yet run through a real weekend since the Sat/Sun-skip feature was added.

**No *research* Claude in the market pipeline — but one cheap enrichment call (as of 2026-08-05):** `generate.js` makes exactly **one** LLM call per day, at the very end of `main()`: `enrichKorean()` sends the already-gathered headlines and change percentages to `claude-haiku-4-5` and gets back Korean one-line summaries (`ko`), a keep/drop flag per headline, and the card's `summary` line. Measured cost is well under a cent a day; it logs its own `usage` and dollar figure like `generate-agenda.js` does. Three rules keep it that way, and they are the whole point:
- **One call, not one per section.** Splitting it by news type re-bills the prompt each time.
- **No search or research tools, ever.** The thing that cost ~$1/day was the `web_search` server tool, *not* summarization — RSS replaced it, and re-adding it would undo the entire 2026-08-05 change.
- **Failure is non-fatal.** A missing `ANTHROPIC_API_KEY`, an API error, or unparseable JSON logs a warning and the briefing is written anyway, just without `ko`/`summary`. Never let this call gate the pipeline.

The paragraph below describes the *research* Claude usage that was removed and must not come back. Earlier versions used the Anthropic Messages API (`claude-sonnet-5` with the `web_search` server tool) first to verify index/stock prices, then (once the Worker took over prices, see below) to research and write Korean-language market news summaries. Both were removed on 2026-08-05: the trigger was cost — the companion "내 주식 현황" portfolio app (`ssangku2-tech/portfolio`) does all of its market data client-side against the same Worker and never calls an LLM, so its bill is near zero, while this app's daily Claude calls were running close to $1/day. Rather than just trim the `web_search` budget further, the user chose to drop AI-written Korean summaries/verification entirely and show raw source headlines instead. Concretely:
- **Prices** (`indices`/`stocks`): fetched directly from a Cloudflare Worker (`stock-proxy.ssangku2.workers.dev`, `?symbol=<ticker>` → `{price, prev, currency}`) — the same personal Worker the portfolio app uses to proxy Yahoo Finance/Naver quotes. Its source is not in this repo; treat its `?symbol=` contract as an external API. This part dates to 2026-08-04 (before the rest of the pipeline dropped Claude too) and works because the cron fires at 06:30 KST, hours after the US regular session closes, so Yahoo's `regularMarketPrice` is already frozen to that day's close. Per-symbol failure still yields `"확인 실패"`, with the existing four-times-a-day retry cron as the safety net — there is no separate fallback path.
- **News** (`news`/`aiNews`/`stocks[].news`): fetched from Google News RSS (`https://news.google.com/rss/search?q=...` — unauthenticated, no key) and parsed with a small hand-rolled regex parser in `generate.js` (`parseRssItems`) instead of an XML library, since this repo intentionally has no `package.json`/dependencies. Items are the *original* title/link/source/date — no Korean translation, no summarization, no "why did it move" commentary. `isFreshEnough()` keeps only items published after the previous briefing's `generatedAt` (its KST timestamp converted to a real instant) so the same story doesn't reappear day after day; comparing by calendar-day string alone was tried first and undercounted fresh items, because the cron's KST 06:30 run instant is still the previous calendar day in UTC (the same class of bug as the weekday check above, fixed together).
- **`sessionDate`/`sessionDateLabel`** (T, the most recently closed US session): computed by `computeSessionDate()` from `dateKey` alone (yesterday, or last Friday if `dateKey` is Monday) — no longer researched. This has **no US-holiday awareness** (a holiday Monday would mislabel T) — acceptable because the Worker's price is always the true latest close regardless of the label; only the display label could read one day off around a US market holiday.
- **`semiconductorNote`/`stockNotes`** (the old per-stock "왜 그렇게 움직였는가" commentary): removed entirely — producing that requires exactly the kind of research/reasoning this change stopped paying for. `stocks` items now only carry a `note` field in the Worker-failure case (`"Worker 조회 실패"`).
- **`summary`**: has had three meanings in one day, so check what produced a given file before trusting it. It began as a mechanical join of the index changePct values (`"S&P 500 +1.79%, 나스닥종합 +2.59%로 마감"`), was removed once the live 지수 스트립 made restating those numbers redundant, and now comes back from `enrichKorean()` as a Claude-written sentence about *what moved the market* — the prompt explicitly forbids listing numbers, precisely because the strip already shows them.

**Per-stock news (2026-08-05):** each `WATCH` entry has a `query` string and `main()` fires one Google News RSS search per stock in parallel, attaching up to 2 items as `stocks[].news`. The queries include the company name, not just the ticker, because bare tickers pull in homonyms (MU→university, AMD→macular degeneration). Freshness is preferred but **not** required here: a single stock's 24-hour window is empty often enough (SKHY especially) that `pickStockNews()` falls back to the single most recent item when nothing is fresh — so the same headline can persist for a few days under a quiet stock. That is deliberate; the alternative is a stock block with a price and nothing else. Palantir is no longer its own news section — PLTR is in `WATCH`, so its news arrives through this path and `aiNews` is Anthropic-only.

If `news`/`aiNews` quality or volume feels off, the first things to check are the RSS query strings in `generate.js` (the `fetchGoogleNewsRSS(...)` call sites in `main()`) and `isFreshEnough`'s cutoff — there is no `web_search`/`effort` budget to tune anymore. (Historical note: between 2026-08-01 and 2026-08-04, `generate.js` made two parallel Claude requests — `marketPrompt` and `aiNewsPrompt` — specifically to stop a shared `web_search` budget from letting semiconductor-price cross-verification starve the AI-news section. That whole mechanism, and the budget-tuning history that went with it, no longer applies now that neither request exists.)

**Agenda pipeline (implemented, 2026-08-02; rewritten 2026-08-03):** `.github/workflows/daily-agenda.yml` runs on its own cron (offset a few minutes from the market workflow's, independent workflow so overlap is harmless, four retry firings same as `generate.js`) and calls `scripts/generate-agenda.js`, which writes `agenda/YYYY-MM-DD.json`. Same skip-if-exists-for-the-day convention as `generate.js` — checked first, before any API calls, since the workflow retries up to four times a day and every retry would otherwise re-call both Google and Anthropic and re-commit. OAuth credentials (`GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET`/`GOOGLE_REFRESH_TOKEN`) are obtained once via `scripts/setup-google-auth.js` (a local one-time script, not run in CI) and stored as GitHub Actions secrets; the Google side is read-only by construction — the OAuth scopes granted (`calendar.readonly`, `gmail.metadata`) cannot write to the calendar or send mail no matter what the code does. `gmail.metadata` (not `gmail.readonly`) is deliberate: it covers everything the script reads (labels, From/Subject headers, snippet) and nothing more, so a leaked CI credential exposes headers rather than every mail body. **The rationale written here until 2026-08-10 was wrong in one respect** — it claimed `gmail.metadata` stays a "sensitive" rather than "restricted" Google scope, and that this is what avoids the formal security assessment. Google classifies `gmail.metadata` as **restricted**, same track as `gmail.readonly`. What actually makes this workable is the *personal use* exception to restricted-scope verification ("you are the only user of your app"), which applies regardless of which of the two scopes is used. So narrowing the scope is still right, just not for the reason recorded — and it never bought a different verification track.

**`gmail.metadata` forbids the `q=` search parameter, and until 2026-08-10 no code here respected that.** Any Gmail call carrying `q=` answers `403 "Metadata scope does not support 'q' parameter"` under this scope. Both `generate-agenda.js` and `index.html` used `q=is:unread`; both now filter with `labelIds=UNREAD&labelIds=INBOX` instead, and the unread total comes from `labels/INBOX`'s `messagesUnread` (an exact count, unlike the `resultSizeEstimate` it replaced). **Do not reintroduce `q=`** — the fix is not to widen the scope back to `gmail.readonly`. Why this hid for so long: the CI refresh token in use from 2026-08-01 to 2026-08-08 was **not** minted by `setup-google-auth.js` at all. The CI OAuth client is a **Web** client (not Desktop, as recorded here until 2026-08-10 — its only registered redirect was `https://developers.google.com/oauthplayground`), and that token was issued through OAuth Playground with `gmail.readonly`, which does accept `q=`. The scope written in this repo only actually took effect on 2026-08-10, when the token was re-minted through the script, and the 403 surfaced immediately. The Desktop-client assumption cost real time during that re-mint; the client now also has `http://127.0.0.1:53682/oauth2callback` registered, so the script path works on it.

**The consent screen's "Testing" status caps refresh tokens at 7 days, and on 2026-08-08 that finally broke the cron for real.** The refresh token was issued 2026-08-01 (`f625b14`); the last successful run was 2026-08-07 23:27 UTC and every firing from 2026-08-08 21:27 UTC on died with `invalid_grant` / `Token has been expired or revoked`. Nothing in the code or the secrets was wrong — the token simply aged out. Two things worth knowing if it happens again: only this workflow is affected (`daily.yml`/`alerts.yml` never touch Google, and the phone's live 일정 keeps working because the GIS token flow issues no refresh token at all — the live 메일 half was in fact broken across this whole window, but for the unrelated `q=` reason above, not the token — what is lost is the `agenda/` file, i.e. the offline fallback, the morning push body, and the Claude-written mail summaries); and **the fix has an order**. Publish the OAuth consent screen to production *first* (Google Cloud Console → API 및 서비스 → OAuth 동의 화면 → 앱 게시), *then* re-run `setup-google-auth.js` and update the `GOOGLE_REFRESH_TOKEN` secret — a token minted while the screen is still in Testing carries the 7-day clock with it, so re-issuing without publishing just buys another week. Publishing unverified means an "확인되지 않은 앱" interstitial during consent (고급 → 이동) and a 100-account cap, neither of which matters for a single personal account.

Calendar: fetches today+tomorrow (KST, converted to UTC for the Calendar API) from the primary calendar; `allDay` = response has `date` but no `dateTime`. Getting the KST day-boundary math wrong is this script's equivalent of the market pipeline's "거래일 혼동" bug — there's no other verification step for calendar data, since it's the user's own already-settled data with nothing to cross-source-verify. Mail: unlike the calendar half, **this half does call the Claude API** (`claude-haiku-4-5`, cheap/fast — deliberately not `claude-sonnet-5`) — it sends only the subject/sender/snippet (never the full body) of up to 15 unread messages and asks Claude to pick up to 5 as "important" with a one-line Korean summary each, filtering out ads/newsletters/automated notices. `unreadCount` is a separate `labels/INBOX` query against Gmail (a real total, not capped by the 15-message detail slice used for the importance pass — and exact, since it reads the label's own `messagesUnread`). Because this is the only LLM call left in the project, `summarizeMails()` logs the response's `usage` and a computed dollar figure (`[claude] claude-haiku-4-5 입력 N · 출력 M 토큰 ≈ $X`) — the Actions log is therefore the place to read *measured* cost rather than estimating it. Ballpark: ~3k input + ~600 output tokens, about $0.006/day (~$0.2/month) at Haiku 4.5's $1/$5 per MTok. A sudden 4× jump means the skip-if-exists guard stopped working and all four retry firings are calling the API. Self-audit is lighter than the market pipeline's — no numeric cross-check needed — but the skip-if-exists check and the separate true-total unread query are the two things that keep this cheap and correct under the four-retries-a-day schedule.

## Commands

There is no build/lint/test tooling for the client. To work on it locally, serve the directory with any static file server (e.g. `npx serve .`) — use a server rather than opening `index.html` via `file://`, since service workers and `fetch` of `briefings/*.json` require an http origin.

To manually generate a day's briefing (normally done by the cron workflow):
```
node scripts/generate.js [YYYY-MM-DD]
```
No API key needed — as of 2026-08-05 this script only talks to the Worker and Google News RSS (see the Generation pipeline note above). Defaults to today in KST if no date given; skips if `briefings/YYYY-MM-DD.json` already exists.

To manually generate a day's agenda (normally done by the cron workflow):
```
GOOGLE_CLIENT_ID=xxx GOOGLE_CLIENT_SECRET=xxx GOOGLE_REFRESH_TOKEN=xxx node scripts/generate-agenda.js [YYYY-MM-DD]
```
To set up the morning push notification (one-time, local — not run in CI):
```
node scripts/setup-push.js
```
It writes the key pair to `push-keys.txt` (gitignored) and prints **only** the file path — the private key deliberately never reaches stdout, because a terminal capture is exactly how it leaks (running this as `! node scripts/setup-push.js` in Claude Code would put stdout straight into the conversation; that happened once, and the key had to be regenerated). Open the file yourself: paste the **public** key into `index.html`'s `VAPID_PUBLIC_KEY` and commit it, put the **private** key in the `VAPID_PRIVATE_KEY` secret, then press 알림 받기 in the app and put the subscription JSON in `PUSH_SUBSCRIPTION`. Delete `push-keys.txt` afterwards. Only two secrets are needed — `send-push.js` reads the public key out of `index.html` rather than taking a third. Details in the Push notifications note below.

Same defaulting/skip behavior as `generate.js`, against `agenda/YYYY-MM-DD.json`. To obtain the three `GOOGLE_*` values in the first place, run `node scripts/setup-google-auth.js` locally once (opens a browser OAuth consent flow, prints the values to your own terminal — never paste them into chat, commits, or logs) after creating a Google Cloud OAuth client; see the Agenda pipeline note above for the scope rationale.

## Architecture

**`index.html`** is the entire application: inline `<style>` for all CSS, inline `<script>` for all logic. There is no router or component framework. The structure is:
- A single `state` object: `{ briefing, shownDate, agenda, agendaDate, live, quoteStatus, liveNews, newsStatus, liveMail, liveEvents, googleStatus, googleError, googleGrants, refreshedAt, refreshing, assetForm, assetError, assetsRevealed, pinPrompt, pinInput, pinError, alertCopied, pushSub, pushError, pushCopied }`.
- One renderer function per card — `renderUSBriefing(b)` (관심 종목/주요 뉴스/앤트로픽), `renderSchedule(a)`, `renderMail(a)`, `renderLearning()`, `renderAssets()`. `renderUSBriefing`/`renderSchedule`/`renderMail` take the *daily file* as their argument and read the live data off `state` — the argument is the fallback, not the source. Each computes its own body HTML (handling its own loading/empty state) and hands it to `cardShell(id, icon, title, sub, bodyHtml, defaultOpen)`, which wraps it in the accordion header (clickable, chevron) and the collapsible `.card-body`. Open/closed state per card id is remembered in `localStorage` (`mycard_open_v1`) via `isCardOpen`/`toggleCard`, overriding `defaultOpen` once the user has toggled a card at least once. `'us'` is the only card with `defaultOpen: true`.
- `renderIndexStrip()` is deliberately *not* a card: the three indices render into `#idx-strip` right under the header so they're readable without expanding anything. Because of it, `renderUSBriefing` no longer emits a 주요 지수 block — don't add one back, it would be the same three numbers twice.
- A single `render()` that fills the header, the 갱신 status line, the index strip, the refresh button's label/subtext, then joins the section strings into `#sections`. It is called after every state change (including `toggleCard`), so it must stay cheap and side-effect-free.

**Data flow:** `refreshAll(force)` is the single entry point — startup, the refresh button, and the `visibilitychange` auto-refresh all call it, so no path can be "more up to date" than another. It sets `state.refreshing`, renders (button reads 갱신 중…), then runs `loadBriefing()` + `loadAgenda()` + `loadQuotes()` + `loadNews()` + `loadGoogleLive(false)` + `loadWeather(force)` in parallel and renders once more. `visibilitychange` re-runs it only when the app has been backgrounded for more than 3 minutes (`AUTO_REFRESH_AFTER`) — an installed PWA can stay alive for days, so without this the user sees yesterday's screen. The refresh button therefore is not the way to get fresh data; it exists for "지금 당장 다시" and for forcing past the weather cache, and its subtext states the last refresh time so the user can tell whether pressing it would change anything.

`loadBriefing()` fetches `briefings/${todayKST()}.json` with `cache:'no-store'`. A 404 is a normal outcome, not an error — it means today's briefing doesn't exist yet. In that case it reads `briefings/index.json` (a sorted array of available date keys) and falls back to the most recent one, recording it in `state.shownDate` so the card can say which day it's showing.

`loadAgenda()` does the same against `agenda/` (`agenda/index.json`, written by `generate-agenda.js` on every run), recording `state.agendaDate`. The fallback is more useful here than it looks: `generate-agenda.js` always fetches **today + tomorrow**, so yesterday's file still contains today's events — `renderSchedule` drops events whose date is before today and shows the rest. Mail has no such property (unread count and the importance pass are that morning's snapshot), so both cards render a `.stale` notice when `isAgendaStale()`. Before 2026-08-05 there was no fallback at all: a missing file rendered the empty state even when yesterday's file held today's schedule.

**Live quotes (`loadQuotes`):** client-side mirrors of `generate.js`'s `INDICES`/`WATCH` drive 10 parallel Worker requests. **The `name`/`ticker` values must stay identical to `generate.js`'s** — `quoteFor()` matches live rows against briefing rows by those keys to swap in the fresh price, and a rename on one side silently reverts that symbol to the 06:30 close. (`WATCH`'s `re` field is client-only — `generate.js` has no equivalent and doesn't need one.) Per-symbol failure is silent and falls back to the briefing file's value; `state.quoteStatus` goes `'fail'` only when *every* symbol failed, and a previous successful `state.live` is kept rather than cleared. `up` is a tri-state here: `true`/`false`/neither (`'확인 실패'` rows from the briefing file), so every renderer picks a class from `up === true ? 'up' : up === false ? 'down' : 'flat'` — never a bare `up ? … : …`, which would paint an unknown value blue for 하락.

**Briefing file shape** (`briefings/YYYY-MM-DD.json`, produced by `scripts/generate.js`), current (2026-08-05+) form:
```json
{
  "date": "2026-08-05",
  "sessionDate": "2026-08-04",
  "sessionDateLabel": "2026년 8월 4일(화) 미국 동부시간 정규장 마감",
  "generatedAt": "2026-08-05 06:30",
  "indices": [{"name":"S&P 500","price":"7,736.52","changePct":"+1.79%","up":true}],
  "news": [{"title":"Dow surges 900 points, S&P 500 closes above 7,700...","link":"https://news.google.com/rss/articles/...","date":"2026-08-04","source":"CNBC"}],
  "stocks": [{"name":"엔비디아","ticker":"NVDA","price":"$211.94","changePct":"+2.56%","up":true,
              "news":[{"title":"Nvidia Tops Key Level As AMD Heads Into Earnings","link":"https://news.google.com/rss/articles/...","date":"2026-08-04","source":"Investor's Business Daily"}]}],
  "aiNews": [{"company":"Anthropic","title":"Anthropic Inks $10 Billion Computing Deal...","link":"https://news.google.com/rss/articles/...","date":"2026-08-04","source":"Bloomberg.com"}]
}
```
`date` is the KST calendar day the file is named for; `sessionDate`/`sessionDateLabel` are the actual US trading day (T) the numbers came from — these can differ (e.g. a Monday-morning KST file reporting Friday's session), and as of 2026-08-05 this is computed by date arithmetic, not researched (see the Generation pipeline note above — no US-holiday awareness). `price`/`changePct` are pre-formatted display strings (the client does no number formatting); `up` is an explicit boolean rather than derived from a signed number. `news`/`stocks`/`aiNews` (and `stocks[].news`) are each optional — the renderers only emit a block for ones that are non-empty, so older or partial briefing files degrade gracefully.

**Almost nothing in this file is what the user normally sees** — as of 2026-08-07 the client overwrites `indices`/`stocks` prices *and* `news`/`aiNews`/`stocks[].news` with values fetched at access time. The file still matters: it is what renders when those fetches fail or the user is offline, and it remains the only source of the Claude-written text (`summary`, `ko`). `sessionDateLabel` is no longer used as the card sub when live news is on (it would date the card to last night's close while the headlines are from minutes ago); it survives as the caption under `summary`, which really is about that session.

Each `news`/`aiNews`/`stocks[].news` item is `{title, link, date, source}` plus an optional **`ko`** — a Korean one-line summary written by `enrichKorean()` — and, at runtime only, **`koT`**, the machine-translated title `translateNews()` attaches in the browser (never written to the JSON files). `title` always stays the untouched original headline (it is what the link goes to, and what both the translation cache and `koMapOf` key on); the Korean forms are what the UI shows. Precedence as of 2026-08-07: 관심 종목 blocks show `ko || koT || title` (one compact line), and 주요 뉴스/앤트로픽 now put `koT || title` in the link with `ko` underneath as the body — i.e. the headline itself reads Korean, and the original survives as the link's `title` attribute rather than as a visible second line (stacking both would double the card's length). Files generated without an API key simply have no `ko` and render in English — that is a supported state, not a bug. Files from before 2026-08-05 instead have `{title, body, date}` (no `link`/`source`) — a Claude-written Korean summary with no source link. `index.html`'s renderers branch on `n.link` being present to support both shapes in the files already committed under `briefings/`; don't remove the `body` branch without migrating or deleting those older files. Pre-2026-08-05 files also carry `semiconductorNote` (no longer rendered) and Palantir entries inside `aiNews` (filtered out by `company`, since Palantir moved to `stocks[].news`). A price/changePct value of `"확인 실패"` means the Cloudflare Worker query for that symbol was unreachable or 404'd at generation time — expected occasionally, not a bug.

**`state`** carries `{ briefing, shownDate, agenda, agendaDate, live, quoteStatus, liveNews, newsStatus, liveMail, liveEvents, googleStatus, googleError, googleGrants, refreshedAt, refreshing, assetForm, assetError, assetsRevealed, pinPrompt, pinInput, pinError, alertCopied, pushSub, pushError, pushCopied }`. Renderers read this global directly rather than taking it as an argument (only `renderUSBriefing(b)`/`renderSchedule(a)`/`renderMail(a)` take their data), so a new card's empty state should follow the same shape.

**Time handling:** all date/time logic is KST, computed by offsetting UTC by +9h (`todayKST`, `hourKST`) rather than using `toLocaleString` with a timezone. `greetingKST()` maps the KST hour to one of five greetings. Keep new time logic on the same +9h-offset approach so the whole app agrees on what "today" is. `sessionDate`/`sessionDateLabel`, by contrast, describe the US trading day and are produced server-side by `generate.js` — the client never computes them.

**Service worker (`sw.js`)** uses a versioned cache name (`daily-brief-vN` — bump on asset changes to bust old caches; currently v33). Fetch handling, in order: non-GET and external API/font hosts bypass the cache entirely (`workers.dev` is in that list and must stay there — caching that Worker would serve a stale price *and* stale news and defeat the whole access-time refresh; `accounts.google.com`/`googleapis.com` were added with live schedule/mail); `/briefings/*` and `/agenda/*` are network-first with a cache fallback (so an offline user still sees the last data they received); **the app shell is network-first too**; everything else (icons, manifest) is cache-first with a background network fill. The app shell (`./`, `index.html`, `manifest.json`) is precached with `addAll` at install; the icons are precached separately with `allSettled` because `addAll` fails the entire install if any one URL 404s.

Two things about the shell branch are load-bearing and easy to undo by accident:
- **It fetches with `cache:'no-store'`, and by URL string rather than passing `e.request`.** GitHub Pages serves `index.html` with `Cache-Control: max-age=600`, so a plain `fetch(e.request)` still lets the browser's HTTP cache return HTML up to 10 minutes old — network-first in the service worker alone does *not* defeat that. The URL-string form is required because a `Request` whose `mode` is `navigate` cannot be passed to `new Request(...)`.
- **It stores the response under the `'./index.html'` cache key**, not under the request URL, so the offline fallback resolves whether the user arrived at `/daily-brief/` or `/daily-brief/index.html`.

**`sw.js` was dead code until 2026-08-05** — `index.html` never called `navigator.serviceWorker.register()`, so nothing was ever precached, no fetch handler ever ran, and every `daily-brief-vN` bump before v20 was ceremonial. The registration was added at the bottom of `index.html`'s script only *after* the shell became network-first; registering it while the shell was still cache-first would have made every deploy land one launch late. If you are debugging "my change isn't showing up", check in this order: (1) is the Pages deploy finished, (2) is the ~10-minute HTTP cache still holding (hard-reload to confirm), (3) service worker state.

## Conventions specific to this codebase

- 단일 `index.html` 구조를 유지할 것 — HTML/CSS/JS를 별도 파일이나 빌드 단계로 분리하지 않는다.
- `index.html` 또는 `sw.js`를 수정할 때는 `sw.js`의 `CACHE` 버전 문자열(`daily-brief-vN`)을 반드시 올린다 — 그렇지 않으면 기존 캐시가 새 자산을 가리지 못한다.
- 커밋 메시지는 한국어로 작성한다.
- 대화는 한국어로 진행한다.
- UI 문구와 코드 주석은 한국어로 작성한다.
- `esc()` must wrap any data-supplied string interpolated into an HTML template string — this app has no framework-level auto-escaping, and briefing content will come from network JSON.
- All colors go through the CSS custom properties in `:root`; don't hardcode hex values in rules. Note the Korean market convention baked into the tokens: `--up` is red, `--down` is blue.
- 새 카드를 추가할 때는 `renderXxx()` 함수 하나를 만들어 본문 HTML을 계산한 뒤 `cardShell(id, icon, title, sub, bodyHtml, defaultOpen)`에 넘기고, 그 결과를 `render()`의 `sections` 배열에 push 하는 패턴을 따른다 — 카드마다 자기 빈 상태는 직접 처리하되, 헤더·접기/펼치기(아코디언)는 `cardShell`에 위임한다. `id`는 다른 카드와 겹치지 않는 짧은 문자열(예: `'us'`, `'mail'`)이어야 한다.
- 날씨 위젯은 Open-Meteo(현재 기온 + 오늘 최고/최저) + BigDataCloud의 클라이언트용 역지오코딩(`reverse-geocode-client`, API 키 불필요)을 함께 쓴다. 결과는 `localStorage`(`myweather_v1`)에 30분간 캐시하고, 캐시가 살아 있으면 위치 권한 조회(`getPosition`)조차 하지 않는다 — 앱을 열 때마다 지오로케이션을 타면 첫 화면이 눈에 띄게 늦다. 새 외부 API를 붙일 때는 `sw.js`의 캐시 우회 목록(`workers.dev`/`open-meteo.com`/`bigdatacloud.net`/`accounts.google.com`/`googleapis.com`/...)에도 호스트를 추가해야 한다 — 안 그러면 서비스워커가 그 응답을 캐시-우선으로 가로챈다.

Worker 호출을 건드릴 때는 `WORKER_URL`이 이 레포 소유가 아닌 외부 계약(포트폴리오 앱의 개인 Cloudflare Worker)이라는 점을, RSS 호출을 건드릴 때는 이 레포에 `package.json`이 없어 XML 파서를 정규식(`parseRssItems`)으로 직접 짰다는 점을 유의한다.
- Mobile-first: the layout is capped at `max-width:520px` and uses `env(safe-area-inset-*)` padding. Test at phone widths, and keep tap targets full-width like `.refresh`.

## Known gaps

**Push notifications (2026-08-05):** one notification a morning, fired by `daily.yml` right after the briefing is committed. Three pieces:
- `scripts/setup-push.js` — local one-time VAPID key generator. It writes to the gitignored `push-keys.txt` and prints only the path; **do not "improve" it by printing the private key**, even for convenience. The first version did print it, and running it as `! node scripts/setup-push.js` put the key straight into the conversation transcript — file output is what makes the documented invocation safe. Only two secrets exist: `VAPID_PRIVATE_KEY` and `PUSH_SUBSCRIPTION`. The public key lives in `index.html` (committed, safe) and `send-push.js` reads it from there, so it can't drift out of sync with what the browser subscribed against. A subscription endpoint is a capability URL — anyone holding it plus the private key can push to the phone — so it must never be committed.
- `scripts/send-push.js` — sends a **payload-free** push. This is the design decision worth preserving: carrying a payload would require ECDH + HKDF + AES-GCM, which means either hand-rolled crypto or the `web-push` package, and this repo has no `package.json`. A bare push needs only a VAPID JWT, which is ~20 lines of `node:crypto`. Two easy-to-miss details: the JWS signature must be P1363 (`dsaEncoding: 'ieee-p1363'`) because Node emits DER by default and push services reject it, and `exp` must be under 24h.
- `sw.js`'s `push` handler — since the push is empty, the handler fetches today's `briefings/` and `agenda/` JSON and builds the text itself. This is why the notification reflects the data at *delivery* time, not send time. `userVisibleOnly: true` obliges it to call `showNotification` on every push, so the body-building is wrapped in try/catch with a fixed fallback string — never add an early return that could skip the call.

**Stock alerts (2026-08-05):** `.github/workflows/alerts.yml` runs `scripts/check-alerts.js` every 30 minutes during both market sessions (KST 09:00–15:30 for KRX, 22:30–05:00 for the US; the US window is padded because DST shifts it an hour) and pushes when a watched symbol moves at least `ALERT_THRESHOLD` percent (default 5) against its previous close. **This is a "something moved, go look" nudge, not a trading signal** — GitHub Actions cron routinely runs tens of minutes late, and nothing here tries to hide that.

- **Which symbols:** the hardcoded `WATCH` list ∪ the optional `ALERT_SYMBOLS` secret. The server cannot read the phone's `localStorage`, so holdings reach it only via the app's 급변동 알림 종목 내보내기 button, which copies `SYMBOL=이름` pairs. It exports **symbols and display names only** — quantities and average prices are deliberately excluded, since the threshold check doesn't need them and including them would put the portfolio's size in a secret. It also exports **every account**, not just the 종합 tab scope the 자산 card displays (see the 자산 card note below for why the two scopes differ). The list goes stale whenever holdings change and has to be re-exported; `WATCH` is always included so a stale secret still leaves the core names covered. `check-alerts.js` keeps its own copy of `WATCH` — keep it in sync with `generate.js`.
- **Dedupe:** `alerts/YYYY-MM-DD.json` records what already fired today, so a stock sitting above the threshold all session alerts once rather than on every cron tick. Nothing is committed and no push is sent when nothing new crosses.
- **How the notification gets its text:** the same payload-free trick as the morning push. `check-alerts.js` writes `alerts/latest.json`, the workflow commits it, **waits 90 seconds for the Pages deploy**, and only then sends the push; `sw.js` fetches that file and shows the names and percentages. The wait is load-bearing — push without it and the service worker reads the previous alert. The handler decides which kind of notification to show by the file's `at` timestamp: fresher than 20 minutes means a stock alert (tag `stock-alert`), otherwise the morning briefing (tag `daily-brief`). 20 minutes is under the 30-minute cron interval, so a stale alert file can't hijack the next morning's briefing.

The briefing send step is gated on `steps.gen.outputs.generated == 'true'`, which `generate.js` writes only when it actually creates a file; the four retry firings therefore produce at most one notification a day. `send-push.js` exits 0 for everything except one case: a **404/410 exits 1 and fails the workflow on purpose**. Those two statuses mean the subscription is permanently gone (notifications turned off, service worker replaced, browser cleanup) and no amount of retrying fixes it — someone has to re-subscribe in the app and update `PUSH_SUBSCRIPTION`. Failing makes GitHub send its "Run failed" mail, which then shows up in the app's own 메일 card; a 410 once passed silently under a green checkmark and went unnoticed for hours. Everything else stays exit 0: missing secrets (notifications are optional and must never break the briefing), and 5xx/429/network errors (transient — the next cron retries, and the alerts workflow runs dozens of times a day, so failing on those would bury the one failure that matters). Both send steps run *after* their data is committed, so a failure here never costs the briefing or the alert record.

- **Amounts are masked by default** in the 자산 card, and the mask state lives in `state.assetsRevealed` — deliberately *not* in `localStorage`, so reopening the app re-hides them. **Unmasking requires the portfolio app's PIN** (2026-08-06): `toggleAssets()` reads that app's `app_pin_hash_v1` (same origin, so it's simply there) and compares against `pinHash()`, which **must stay byte-identical to the portfolio app's `simpleHash`** — it is not a hash this repo chose, it's the one that produced the stored value. - **Rows are ordered by evaluated value, descending** (2026-08-06): `renderAssets()` sorts a `slice()` of the holdings — never the array itself, since `effectiveHoldings()`'s result is also what `exportAlertSymbols()` walks — using a KRW-normalized key (`price × qty × fx` for USD), because comparing raw numbers would rank a $200 position above a ₩200,000 one. Holdings whose quote didn't arrive sort to the bottom (key `-1`), which is also where they belong visually since they render a shorter row. - **A holding row is three columns, and its height is the constraint** (2026-08-06): 이름/수량 · 현재가/전일 대비 %/당일 손익 · 평가액/누적 손익/누적 %.
